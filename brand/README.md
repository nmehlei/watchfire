# Watchfire brand assets

The mark is an aperture: eight blades pinwheeling around an octagonal pupil,
drawn on a 24-unit grid so it survives being rendered at 16px. Every asset in
this directory is generated by `brand/build.mjs` from one geometry
definition — **never hand-edit the SVGs**. If a shape needs to change, change
the parameters (or the maths) in `build.mjs` and regenerate:

```bash
node brand/build.mjs
```

## Palette

| Role | Light theme | Dark theme |
|---|---|---|
| Blade (light facet) | `#6D7BFF` | `#95A0FF` |
| Blade (deep facet) | `#4C5BD4` | `#6D7BFF` |
| Pupil (warm accent) | `#FFB454` | `#FFC46B` |
| App icon tile ground | `#0B1020` | — |
| Lockup wordmark | `#0B1020` (on light) | `#E6EAF2` (on dark) |

Deep ink ground, one cool indigo/blue accent split across two tones for the
blade alternation, one warm amber pupil as the focal point. Monochrome mode
(`mark-mono.svg`) drops all of this and uses `currentColor` throughout,
including the pupil.

## Which file to use where

- `mark.svg` — on light backgrounds.
- `mark-dark.svg` — on dark backgrounds.
- `mark-mono.svg` — wherever the mark must inherit a single text/icon color
  (`currentColor`). Only works when the SVG is inlined into the page/app, not
  when loaded via `<img src>` — that always resolves `currentColor` to black
  regardless of surrounding CSS.
- `lockup.svg` / `lockup-dark.svg` — mark + "Watchfire" wordmark, for headers and
  title bars, on light and dark backgrounds respectively.
- `app-icon.svg` — the mark on an ink tile inside the maskable safe area, for
  app/home-screen icons.

## Minimum size and clear space

- Minimum size: **16px.** Below that the blade gaps and pupil start to
  degrade.
- Clear space: leave empty space around the mark equal to at least **half
  the mark's width** on every side before placing other content (text,
  edges, other logos).

## Source of truth

`brand/build.mjs` is the only place the geometry is defined. All six SVGs
(`mark.svg`, `mark-dark.svg`, `mark-mono.svg`, `lockup.svg`,
`lockup-dark.svg`, `app-icon.svg`) are build output — regenerate them with
`node brand/build.mjs` rather than editing the files directly.

## Where the dashboard uses it

| Dashboard file | Source |
|---|---|
| `apps/dashboard/src/app/icon.svg` | copy of `app-icon.svg` — served by Next as the tab icon |
| `apps/dashboard/public/icons/icon-192.png` | `app-icon.svg` rendered at 192×192 — PWA manifest |
| `apps/dashboard/public/icons/icon-512.png` | `app-icon.svg` rendered at 512×512 — PWA manifest |

These are copies, so regenerate them whenever `app-icon.svg` changes.

## Regenerating the PNGs

No rasteriser is required beyond Chrome. From the repository root:

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
for size in 192 512; do
  printf '<!doctype html><body style="margin:0"><img src="file://%s/brand/app-icon.svg" width="%s" height="%s" style="display:block"></body>' \
    "$PWD" "$size" "$size" > "/tmp/iris-icon-$size.html"
  "$CHROME" --headless=new --hide-scrollbars --force-device-scale-factor=1 \
    --window-size="$size,$size" --screenshot="apps/dashboard/public/icons/icon-$size.png" \
    "file:///tmp/iris-icon-$size.html"
done
cp brand/app-icon.svg apps/dashboard/src/app/icon.svg
sips -g pixelWidth -g pixelHeight apps/dashboard/public/icons/icon-*.png
```

The last line must report exactly 192×192 and 512×512. An off-size result means
the page gained a margin or scrollbar — fix the HTML rather than accepting it.
The area outside the rounded tile renders white; that is fine, because the
manifest declares both icons `maskable` and the platform crops to its own shape.
