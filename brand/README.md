# Watchfire brand assets

The mark is a **shield holding a fire**. The shield says the agent guards without
touching anything; the fire is the watchfire itself — a signal kept burning through
the night so someone can see what is wrong. Navy body, ember flame.

Every asset here is generated by `brand/build.mjs` from one definition —
**never hand-edit the SVGs**. To change a shape or a colour, change it in the
generator and regenerate:

```bash
node brand/build.mjs
```

## Palette

| Role | Light backgrounds | Dark backgrounds |
|---|---|---|
| Shield, top of gradient | `#2E5FB8` | `#4C82E8` |
| Shield, bottom of gradient | `#0E2A5C` | `#17407F` |
| Flame, base | `#E8471F` | `#E8471F` |
| Flame, mid | `#FF8A1E` | `#FF9A2E` |
| Flame, tip | `#FFD166` | `#FFDC8A` |
| Inner core, tip | `#FFF3D0` | `#FFF3D0` |
| App icon tile | `#0B1020` | `#0B1020` |
| Wordmark | `#0B1020` | `#E9ECF5` |

The dark variants lift the navy a step so the shield keeps its edge against a dark
page instead of dissolving into it. The flame stays warm in both, which is what
carries the "fire" reading at small sizes.

## Which file to use where

- `mark.svg` — on light backgrounds.
- `mark-dark.svg` — on dark backgrounds.
- `mark-mono.svg` — where the mark must take a single surrounding colour. The flame
  is knocked out of the shield and the fill is `currentColor`, so it adapts — but
  **only when the SVG is inlined**. Loaded through `<img src>` it always renders
  black, whatever the surrounding CSS says.
- `mark-outline.svg` — lighter weight, for dense UI where the solid shield is too heavy.
- `lockup.svg` / `lockup-dark.svg` — mark plus the "Watchfire" wordmark, for headers.
- `app-icon.svg` — the mark on an ink tile inside the maskable safe area, for app and
  home-screen icons.

## Minimum size and clear space

- Minimum size: **16px**. The shield silhouette still reads at that size; the flame
  becomes a warm centre rather than a distinct shape, which is the intended behaviour.
- Clear space: leave at least **half the mark's width** on every side before placing
  other content.

## Where the dashboard uses it

| Dashboard file | Source |
|---|---|
| `apps/dashboard/src/app/icon.svg` | copy of `app-icon.svg` — served by Next as the tab icon |
| `apps/dashboard/public/icons/icon-192.png` | `app-icon.svg` rendered at 192×192 — PWA manifest |
| `apps/dashboard/public/icons/icon-512.png` | `app-icon.svg` rendered at 512×512 — PWA manifest |

These are copies, so regenerate them whenever `app-icon.svg` changes.

## Regenerating the PNGs

No rasteriser is needed beyond Chrome. From the repository root:

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
for size in 192 512; do
  printf '<!doctype html><body style="margin:0"><img src="file://%s/brand/app-icon.svg" width="%s" height="%s" style="display:block"></body>' \
    "$PWD" "$size" "$size" > "/tmp/wf-icon-$size.html"
  "$CHROME" --headless=new --hide-scrollbars --force-device-scale-factor=1 \
    --window-size="$size,$size" --screenshot="apps/dashboard/public/icons/icon-$size.png" \
    "file:///tmp/wf-icon-$size.html"
done
cp brand/app-icon.svg apps/dashboard/src/app/icon.svg
sips -g pixelWidth -g pixelHeight apps/dashboard/public/icons/icon-*.png
```

The last line must report exactly 192×192 and 512×512. An off-size result means the
page gained a margin or a scrollbar — fix the HTML rather than accepting it.
